# DECISIONS.md

## Вариант

Номер варианта: (35 mod 8) + 1 = 4.

Изменяемый аспект — ставка НДС, параметр 25: НДС = 25 % от стоимости после скидки.
Правило сосредоточено в одной константе `VAT_RATE = 25.0` класса `OrderCalculator`
и применяется только в вызове `calculateVat(afterDiscount, VAT_RATE)`.

## Решение 1

Формулировка: каждая формула записана в отдельном методе один раз (`calculateBase`,
`calculateDiscountAmount`, `applyDiscount`, `calculateVat`, `calculateTotal`), а `main` только
вызывает их по порядку и выводит результат.

Альтернатива: записать все вычисления одной строкой прямо в `main`.

Обоснование: формула не повторяется, каждую можно проверить отдельно в `SelfCheck`, а правило
«НДС после скидки» видно по тому, что `calculateVat` получает результат `applyDiscount`.

## Решение 2

Формулировка: ввод проверяется в два этапа — сначала формат (`parseQuantity`, `parseAmount`:
пусто, не число, дробное количество), затем диапазоны (`validate` / `isValid`). Расчёт выполняется
только при `validate(...) == null`. Все границы вынесены в константы.

Альтернатива: читать значения через `nextInt()` / `nextDouble()` и проверять диапазоны внутри формул.

Обоснование: `nextInt()` падает с `InputMismatchException` на «abc», а проверка до расчёта
гарантирует, что при ошибке выводится понятное сообщение и ни одна сумма не печатается.

## Выбор типов

`int` — для количества: оно целое, а диапазон 1…10000 помещается в `int` с запасом.
`double` — для цены, процента скидки и сумм: они дробные.
Ограничение `double`: десятичные дроби (например, 0.1) хранятся в двоичном виде приближённо,
поэтому при многих операциях возможна ошибка в последних разрядах. Для денежных расчётов
в реальной системе лучше `BigDecimal` или целые копейки в `long`. В работе результат
округляется только при выводе (`%.2f`), итоги сверены с расчётом на `BigDecimal`.

## Фрагмент кода для анализа

```java
double total = price * quantity - discount;
```

Скидка задана в процентах, а фрагмент вычитает её как рубли. Для 10 × 1500.50 и скидки 10 %
он даёт 15005.00 − 10 = 14995.00, хотя верная стоимость после скидки 13504.50 (скидка 1500.50).
Кроме того, НДС не начисляется вовсе. Исправленный подход: `base` → `discount = base × d / 100`
→ `afterDiscount = base − discount` → `vat = afterDiscount × 25 / 100` → `total = afterDiscount + vat`.
